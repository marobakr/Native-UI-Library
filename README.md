# Vodafone Egypt Native UI Library

Framework-independent web component library for Liferay and other CMS platforms.

## Overview

This library provides native HTML/CSS/JavaScript components based on the Vodafone Egypt design system. The components are:

- **Framework-independent** - Work in any environment (Liferay, vanilla JS, React, Vue, etc.)
- **Accessible** - WCAG 2.1 AA compliant with keyboard and screen reader support
- **RTL/LTR Ready** - Full bidirectional text support for multilingual contexts
- **Design Token-Driven** - Consistent theming via CSS custom properties
- **Progressive Enhancement** - Work without JavaScript, enhanced with JavaScript

### How It Works

The migration system:
- ✅ Discovers Angular library automatically
- ✅ Extracts design tokens from source (verified)
- ✅ Builds component inventory
- ✅ Migrates components in dependency order
- ✅ Verifies every value against source
- ✅ Records missing information (never invents)
- ✅ Creates checkpoints for resumability
- ✅ Works autonomously until done

See **[AUTONOMOUS-MIGRATION.md](./AUTONOMOUS-MIGRATION.md)** for architecture details.

## Architecture

### Core Principles

1. **HTML-First** - Component structure is explicit in HTML, not generated by JavaScript
2. **CSS Tokens** - All styling uses CSS custom properties (design tokens)
3. **CMS-Independent** - No Liferay or CMS-specific code in components
4. **Progressive Enhancement** - Core functionality in HTML/CSS, enhanced with JavaScript

### Technology Stack

- **HTML5** - Semantic markup
- **CSS3** - Modern CSS with custom properties
- **JavaScript (ES6+)** - Modern JavaScript, no transpilation
- **Vitest** - Testing framework
- **Vite** - Build tool and dev server

## Component Development

### Workflow

```
Discovery → Analysis → Conversion → Validation → Integration
```

1. **Discovery** - Explore Angular library, identify components
2. **Analysis** - Deep dive into specific component
3. **Conversion** - Implement as native web component
4. **Validation** - Test thoroughly (functionality, accessibility, performance)
5. **Integration** - Create Liferay fragments and documentation

### Creating a Component

Each component follows this structure:

```
src/components/button/
├── button.html          # Component markup template
├── button.css           # Component styles (using tokens)
├── button.js            # Component behavior
├── button.test.js       # Unit tests
└── README.md            # Component documentation
```

### Key Rules

#### HTML Structure
- ✅ Explicit HTML structure in `.html` file
- ✅ Semantic HTML5 elements
- ✅ ARIA attributes for accessibility
- ❌ NO dynamic structure generation in JavaScript

#### CSS Styling
- ✅ Use design tokens (CSS custom properties)
- ✅ Logical properties for RTL support
- ✅ BEM naming convention
- ❌ NO hard-coded values (colors, sizes, etc.)

#### JavaScript Behavior
- ✅ ES6+ modern syntax
- ✅ Progressive enhancement
- ✅ Clean up event listeners
- ❌ NO framework dependencies

## Design Tokens

⚠️ **Design tokens are currently placeholders** and must be extracted from the Angular UI Library.

**Token Structure:**
```
tokens/
├── theme.css         # Main theme file
├── colors.css        # Brand and semantic colors
├── typography.css    # Font families, sizes, weights
├── spacing.css       # Spacing scale
├── borders.css       # Border widths and radii
├── shadows.css       # Box shadows
└── transitions.css   # Animation durations
```

**To populate tokens:**
1. Inspect Angular library:https://git.vf-eg.internal.vodafone.com/WEB/vf-dynamic-catalog-components/-/tree/master
2. Extract actual Vodafone design values
3. Update token files

See [TOKENS-README.md](./TOKENS-README.md) for detailed extraction guide.

All components will use these tokens for consistent styling:
```css
.vf-button {
  background: var(--vf-color-primary);
  padding: var(--vf-space-md);
}
```

## Liferay Integration

The native components integrate with Liferay through:

1. **Liferay Fragments** - Component wrappers with configuration
2. **Theme Integration** - Library loaded via theme resources
3. **Content Mapping** - Web content mapped to component props

Integration documentation will be in `liferay-integration/` (created later).

**Important:** The core library is CMS-independent. Liferay-specific code lives in fragments, not in components.

## Accessibility

All components must meet **WCAG 2.1 AA** standards:

- ✅ Semantic HTML elements
- ✅ Proper ARIA attributes
- ✅ Keyboard navigation (Tab, Enter, Escape, Arrows)
- ✅ Screen reader support
- ✅ Color contrast ≥ 4.5:1
- ✅ Touch targets ≥ 44x44px
- ✅ Focus visible

## RTL/LTR Support

All components support bidirectional text:

- Layout mirrors in RTL languages (Arabic)
- Uses CSS logical properties
- Directional icons flip appropriately
- Works with `dir="rtl"` attribute
